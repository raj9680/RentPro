RentPro HttpClient Reference

How the MVC app calls the API with HttpClient: setup, token, and one recipe per request type. These patterns work in any ASP.NET Core MVC app that calls a JSON API. Only the URLs and DTO names are RentPro-specific.

1. How HttpClient works

HttpClient is the C# class that sends HTTP requests and reads responses: what Postman or a browser does, done from code. In an MVC app, the browser never talks to the API. The MVC controller does, using HttpClient.

Flow
Browser ──form post──►  MVC controller  ──HttpClient──►  Rent.API controller
   ▲                         │  ▲                              │
   │                         │  └──── JSON (ApiResponse) ──────┘
   └────── HTML page ◄───────┘

A request has four parts

PartExampleNotes
MethodGET POST PUT PATCH DELETEWhat you want to do
URLhttps://localhost:7001/api/properties/600001BaseAddress + path
HeadersAuthorization: Bearer eyJhbGciOi...
Content-Type: application/json		Token and body type
Body{ "name": "Lake View PG", "city": "Noida" }JSON of a request DTO. None for GET and DELETE

A response has three parts

PartExample
Status code200 201 400 401 404 409 500
HeadersContent-Type: application/json; charset=utf-8
BodyThe ApiResponse envelope: { success, data, message, errors }

Which method for what

MethodUse forBody?
GETRead one item or a listNo
POSTCreate, login, register, actions (check-out, pay)Yes
PUTReplace all editable fieldsYes
PATCHChange only some fieldsYes
DELRemove an itemNo
HTML forms can only send GET and POST. The browser always posts to an MVC action; the MVC action then sends PUT, PATCH or DELETE to the API with HttpClient.

2. Setup

Register once in Program.cs; every controller then gets a ready-to-use client by constructor injection.

Three ways to get an HttpClient

WayExampleVerdict

3. Core classes

Two small classes do all the HTTP work. Controllers never touch HttpClient directly.

Shared DTOs

MVC sends and reads the same JSON shapes as the API, so it reuses the classes from Rent.Contracts: request/response DTOs, ApiResponse<T> and PagedResponse<T>.

ApiResponse<T> currently lives in Rent.API/Common. MVC cannot reference Rent.API, so ApiResponse<T> and PagedResponse<T> need to move to Rent.Contracts (or be copied into MVC). Not decided yet.

    public List<T> Items { get; set; } = new();
    public int Page { get; set; }
    public int PageSize { get; set; }
    public int TotalCount { get; set; }

    public bool HasNext => Page < TotalPages;

ApiResult<T>: what every call returns

using System.Net;

namespace Rent.Web.Services.Api;

public class ApiResult<T>
{
    public HttpStatusCode StatusCode { get; init; }
    public bool Success { get; init; }
    public T? Data { get; init; }
    public string? Message { get; init; }
    public Dictionary<string, string[]>? Errors { get; init; }

    // 400 and 409 are shown on the form; everything else is handled centrally
    public bool IsFormError =>
        StatusCode is HttpStatusCode.BadRequest or HttpStatusCode.Conflict;

    public static ApiResult<T> Fail(HttpStatusCode statusCode, string message) =>
        new() { StatusCode = statusCode, Success = false, Message = message };
}

ApiClient: the typed client

Services/Api/ApiClient.cs
using System.Net;
using System.Net.Http.Json;
using System.Text.Json;
using Rent.Contracts; // ApiResponse<T>

namespace Rent.Web.Services.Api;

public class ApiClient
{
    private readonly HttpClient _http;
    private readonly ILogger<ApiClient> _logger;

    public ApiClient(HttpClient http, ILogger<ApiClient> logger)
    {
        _http = http;
        _logger = logger;
    }

    public Task<ApiResult<T>> GetAsync<T>(string url, CancellationToken ct = default)
        => SendAsync<T>(HttpMethod.Get, url, null, ct);

    public Task<ApiResult<T>> PostAsync<T>(string url, object? body, CancellationToken ct = default)
        => SendAsync<T>(HttpMethod.Post, url, body, ct);

    public Task<ApiResult<T>> PutAsync<T>(string url, object body, CancellationToken ct = default)
        => SendAsync<T>(HttpMethod.Put, url, body, ct);

    public Task<ApiResult<T>> PatchAsync<T>(string url, object body, CancellationToken ct = default)
        => SendAsync<T>(HttpMethod.Patch, url, body, ct);

    public Task<ApiResult<T>> DeleteAsync<T>(string url, CancellationToken ct = default)
        => SendAsync<T>(HttpMethod.Delete, url, null, ct);

    private async Task<ApiResult<T>> SendAsync<T>(
        HttpMethod method, string url, object? body, CancellationToken ct)
    {
        using var request = new HttpRequestMessage(method, url);
        if (body is not null)
            request.Content = JsonContent.Create(body); // JSON + Content-Type header

        try
        {
            using var response = await _http.SendAsync(request, ct);
            var envelope = await TryReadEnvelopeAsync<T>(response, ct);

            return new ApiResult<T>
            {
                StatusCode = response.StatusCode,
                Success = response.IsSuccessStatusCode,
                Data = envelope is null ? default : envelope.Data,
                Message = envelope?.Message ?? DefaultMessage(response.StatusCode),
                Errors = envelope?.Errors
            };
        }
        catch (HttpRequestException ex) // API not running, DNS, SSL
        {
            _logger.LogError(ex, "API unreachable: {Method} {Url}", method, url);
            return ApiResult<T>.Fail(HttpStatusCode.ServiceUnavailable,
                "The service is not available. Please try again later.");
        }
        catch (TaskCanceledException ex) when (!ct.IsCancellationRequested) // timeout
        {
            _logger.LogError(ex, "API timeout: {Method} {Url}", method, url);
            return ApiResult<T>.Fail(HttpStatusCode.GatewayTimeout,
                "The request took too long. Please try again.");
        }
    }

    // Some responses have no JSON body (e.g. a 401 from [Authorize]); never crash on them
    private static async Task<ApiResponse<T>?> TryReadEnvelopeAsync<T>(
        HttpResponseMessage response, CancellationToken ct)
    {
        var mediaType = response.Content.Headers.ContentType?.MediaType;
        if (mediaType is null || !mediaType.Contains("json"))
            return null;

        try
        {
            return await response.Content.ReadFromJsonAsync<ApiResponse<T>>(ct);
        }
        catch (JsonException)
        {
            return null;
        }
    }

    private static string? DefaultMessage(HttpStatusCode code) => code switch
    {
        HttpStatusCode.Unauthorized => "Your session has expired. Please log in again.",
        HttpStatusCode.Forbidden => "You do not have permission to perform this action.",
        HttpStatusCode.NotFound => "The requested item was not found.",
        _ when (int)code < 300 => null,
        _ => "Something went wrong. Please try again."
    };
}

What ApiClient handles for you

SituationWithout ApiClientWith ApiClient

401 with an empty bodyJsonException crashDefault message, status 401

By default, ASP.NET Core returns an empty body for a 401 from [Authorize] (JWT missing or expired). That is why ApiClient reads the body only when it is JSON.

4. Bearer token handler

A DelegatingHandler sits between ApiClient and the network. It runs on every request, so no controller ever sets the Authorization header.

Pipeline
ApiClient.SendAsync
      │
      ▼
BearerTokenHandler   reads the JWT from the login cookie
      │              adds: Authorization: Bearer eyJhbGciOi...
      ▼
Network  ───────────►  Rent.API  (JwtBearer validates the token)
Services/Api/BearerTokenHandler.cs
using System.Net.Http.Headers;
using Microsoft.AspNetCore.Authentication;

namespace Rent.Web.Services.Api;

public class BearerTokenHandler : DelegatingHandler
{
    private readonly IHttpContextAccessor _httpContextAccessor;

    public BearerTokenHandler(IHttpContextAccessor httpContextAccessor)
    {
        _httpContextAccessor = httpContextAccessor;
    }

    protected override async Task<HttpResponseMessage> SendAsync(
        HttpRequestMessage request, CancellationToken cancellationToken)
    {
        var httpContext = _httpContextAccessor.HttpContext;
        if (httpContext is not null)
        {
            // Saved at login with props.StoreTokens(...) (Section 7)
            var token = await httpContext.GetTokenAsync("access_token");
            if (!string.IsNullOrEmpty(token))
                request.Headers.Authorization = new AuthenticationHeaderValue("Bearer", token);
        }

        return await base.SendAsync(request, cancellationToken);
    }
}
RequestToken in cookie?Header sent
Login / RegisterNo (not logged in yet)None. The API endpoints allow anonymous calls
Any call after loginYesAuthorization: Bearer eyJ...
After the cookie expiredNo (cookie gone)None; MVC [Authorize] redirects to Login before the call

6. Handling API results in MVC

Every recipe below follows the same pattern: success → view or redirect; 400/409 → show on the form; anything else → HandleFailureAsync.

API statusTypical causeMVC does
200 201SuccessShow the view, or redirect after a POST
400Validation failedCopy errors into ModelState, show the form again
401Token missing or expiredSign out the cookie, redirect to Login with returnUrl
403Wrong role, not the ownerRedirect to AccessDenied
404Id does not existReturn NotFound()
409Business rule (duplicate, double booking)Form: error on the form. Button: TempData error
500 503 504Server error, API down, timeoutError page with the generic message
Post/Redirect/Get: after a successful POST, always redirect. Returning a view directly makes the browser re-submit the form when the user presses refresh.
Extensions/ModelStateExtensions.cs
using Microsoft.AspNetCore.Mvc.ModelBinding;
using Rent.Web.Services.Api;

namespace Rent.Web.Extensions;

public static class ModelStateExtensions
{
    public static void AddApiErrors<T>(this ModelStateDictionary modelState, ApiResult<T> result)
    {
        if (result.Errors is { Count: > 0 })
        {
            // "Email": ["..."] lands next to the Email input
            foreach (var (field, messages) in result.Errors)
                foreach (var message in messages)
                    modelState.AddModelError(field, message);
        }
        else
        {
            // Empty key = form-level error (validation summary)
            modelState.AddModelError(string.Empty, result.Message ?? "Something went wrong.");
        }
    }
}
Controllers/AppController.cs
using System.Net;
using Microsoft.AspNetCore.Authentication;
using Microsoft.AspNetCore.Authentication.Cookies;
using Microsoft.AspNetCore.Mvc;
using Rent.Web.Services.Api;

namespace Rent.Web.Controllers;

public abstract class AppController : Controller
{
    // For failures that the page itself cannot fix
    protected async Task<IActionResult> HandleFailureAsync<T>(ApiResult<T> result)
    {
        switch (result.StatusCode)
        {
            case HttpStatusCode.Unauthorized:
                await HttpContext.SignOutAsync(CookieAuthenticationDefaults.AuthenticationScheme);
                return RedirectToAction("Login", "Account",
                    new { returnUrl = Request.Path + Request.QueryString });

            case HttpStatusCode.Forbidden:
                return RedirectToAction("AccessDenied", "Account");

            case HttpStatusCode.NotFound:
                return NotFound();

            default:
                ViewData["Message"] = result.Message;
                return View("ApiError");
        }
    }
}

POST 7. Login

The MVC app logs in through the API, then keeps the user signed in with its own cookie.

POST api/auth/login
Flow
1. Browser posts the form        → MVC Login(model)
2. MVC calls the API             → POST api/auth/login
3. API returns token + expiresAt + user
4. MVC builds claims             → who the user is
5. MVC sets cookie expiry        → = token expiresAt
6. MVC stores the JWT            → inside the encrypted cookie
7. SignInAsync writes the cookie → redirect to returnUrl or Home
Controllers/AccountController.cs (login part)
using System.Security.Claims;
using Microsoft.AspNetCore.Authentication;
using Microsoft.AspNetCore.Authentication.Cookies;
using Microsoft.AspNetCore.Authorization;
using Microsoft.AspNetCore.Mvc;
using Rent.Contracts;              // LoginRequest, LoginResponse, RegisterRequest
using Rent.Web.Extensions;
using Rent.Web.Services.Api;

namespace Rent.Web.Controllers;

public class AccountController : AppController
{
    private readonly ApiClient _api;

    public AccountController(ApiClient api)
    {
        _api = api;
    }

    [HttpGet]
    [AllowAnonymous]
    public IActionResult Login(string? returnUrl = null)
    {
        ViewData["ReturnUrl"] = returnUrl;
        return View();
    }

    [HttpPost]
    [AllowAnonymous]
    [ValidateAntiForgeryToken]
    public async Task<IActionResult> Login(LoginRequest model, string? returnUrl, CancellationToken ct)
    {
        ViewData["ReturnUrl"] = returnUrl;
        if (!ModelState.IsValid)
            return View(model);

        var result = await _api.PostAsync<LoginResponse>("api/auth/login", model, ct);

        // Wrong password (401), inactive (403), validation (400), API down (503):
        // all shown on the login form
        if (!result.Success || result.Data is null)
        {
            ModelState.AddApiErrors(result);
            return View(model);
        }

        var login = result.Data;

        // Who the user is
        var claims = new List<Claim>
        {
            new(ClaimTypes.Email, model.Email),
            new(ClaimTypes.Name, login.User.FullName),
            new(ClaimTypes.Role, login.User.Role),
            new("Status", login.User.Status)
        };
        var identity = new ClaimsIdentity(claims, CookieAuthenticationDefaults.AuthenticationScheme);

        // Cookie expires exactly when the token expires
        var expiresAtUtc = DateTime.SpecifyKind(login.ExpiresAt, DateTimeKind.Utc);
        var props = new AuthenticationProperties
        {
            IsPersistent = true,
            ExpiresUtc = new DateTimeOffset(expiresAtUtc),
            AllowRefresh = false
        };

        // JWT kept inside the encrypted cookie; BearerTokenHandler reads it back
        props.StoreTokens(new[]
        {
            new AuthenticationToken { Name = "access_token", Value = login.AccessToken }
        });

        await HttpContext.SignInAsync(
            CookieAuthenticationDefaults.AuthenticationScheme,
            new ClaimsPrincipal(identity),
            props);

        if (!string.IsNullOrEmpty(returnUrl) && Url.IsLocalUrl(returnUrl))
            return Redirect(returnUrl);

        return RedirectToAction("Index", "Home");
    }
}

[HttpGet]
public async Task<IActionResult> Index([FromQuery] PropertyQuery query, CancellationToken ct)
{
    var parameters = new Dictionary<string, string?>
    {
        ["page"] = query.Page.ToString(),
        ["pageSize"] = query.PageSize.ToString(),
        ["search"] = query.Search,
        ["city"] = query.City,
        ["sortBy"] = query.SortBy,
        ["sortOrder"] = query.SortOrder
    };

    // Skips empty values and URL-encodes the rest ("New Delhi" -> "New%20Delhi")
    var url = QueryHelpers.AddQueryString("api/properties",
        parameters.Where(p => !string.IsNullOrEmpty(p.Value)));

    var result = await _api.GetAsync<PagedResponse<PropertySummaryResponse>>(url, ct);

    if (!result.Success)
        return await HandleFailureAsync(result);

    ViewData["Query"] = query;   // to keep filters in the pager links
    return View(result.Data);
}

POST 11. Create

The pattern used by every form: validate, call, then redirect, show the form again, or handle centrally.

POST api/properties
PropertiesController.cs
[HttpGet]
public IActionResult Create() => View(new CreatePropertyRequest());

[HttpPost]
[ValidateAntiForgeryToken]
public async Task<IActionResult> Create(CreatePropertyRequest model, CancellationToken ct)
{
    if (!ModelState.IsValid)
        return View(model);   // MVC checks the DTO attributes first; no API call

    var result = await _api.PostAsync<PropertyResponse>("api/properties", model, ct);

    if (result.Success)
    {
        TempData["Success"] = result.Message;   // "Property created successfully."
        return RedirectToAction(nameof(Details), new { id = result.Data!.Id });
    }

    if (result.IsFormError)   // 400 validation, 409 duplicate
    {
        ModelState.AddApiErrors(result);
        return View(model);
    }

    return await HandleFailureAsync(result);
}
APIMVC result
201Redirect to Details of the new Id, success message
400Same form, errors next to fields
409Same form, "A property with this name already exists."
401 403 500HandleFailureAsync
Validation runs twice on purpose: MVC catches simple mistakes without a network call; the API stays the final authority.

16. Common mistakes

Most HttpClient bugs come from this list.

MistakeWhat goes wrongDo this instead
new HttpClient() per requestConnections run out under loadTyped client via AddHttpClient<ApiClient>
BaseAddress without a trailing /Part of the URL is silently droppedEnd BaseAddress with /; no leading / on paths
GetFromJsonAsync on an API with error bodiesThrows on 404; the message is lostSendAsync via ApiClient
.Result or .Wait()Blocked threads, possible deadlocksasync/await all the way
JWT in localStorage or page JavaScriptReadable by any injected scriptKeep it inside the HttpOnly cookie
Id, Role, OwnerId taken from the formUsers can change themThe API sets them
Missing [ValidateAntiForgeryToken]Other sites can submit forms as the userAdd it to every POST action
Delete or logout via a GET linkTriggered by prefetch or other sitesPOST form
Query string built with +Breaks on spaces and &amp;QueryHelpers.AddQueryString
Returning a view after a successful POSTRefresh re-submits the formRedirect (Post/Redirect/Get)
Showing the raw exceptionLeaks internalsGeneric message; real error in the log
ApiClient injected into a singletonThe HttpClient is captured and never refreshedUse it in controllers or scoped services
